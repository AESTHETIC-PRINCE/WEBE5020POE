## 1. Project overview

Aesthetic Surveillance is a proposed South African security business offering six services: **drone surveillance, secure transport, VIP and executive protection, armed response, site security and security consultation**. The website presents the brand in a black / white / gold luxury style, explains the services, and lets visitors request an instant indicative estimate or contact the team.

**Goals:** look credible and premium; explain each service clearly; convert visitors into enquiries; make the nearest office easy to find.
**Target audience:** private clients, celebrities and executives, business owners, event organisers.

### How the form processing works

* **Enquiry estimate** = units × day-rate × days, plus a priority surcharge (Priority +25%, Emergency +50%), minus a longer-booking discount (5% from 7 days, 10% from 14 days). The page shows a ±10% range, excluding VAT. Day-rates are *illustrative* figures stored in `js/script.js` (`SERVICES`).
* **Contact email:** change the single line `CONTACT_EMAIL` at the top of `js/script.js` to set the recipient. The form needs no server — it uses a `mailto:` link.
* Validation covers South African phone numbers, future-only dates (within 12 months), whole-number limits, minimum/maximum message length, and a hidden honeypot field to catch bots. Visitor text is only ever inserted with `textContent`, never `innerHTML`.

## 5. SEO implementation

| Item | Implementation |
|---|---|
| **Title tags** | Unique, 39–56 characters, keyword first, brand last (Google, 2026b) |
| **Meta descriptions** | Unique, 97–152 characters, written for a human reader |
| **Meta keywords** | Unique list per page (search engines such as Google ignore this tag today, but it is included as the brief requires) |
| **Images** | Descriptive file names (e.g. `armoured-suv-secure-transport.webp`), meaningful `alt` text, `width`/`height` set, `loading="lazy"` below the fold |
| **Headings** | Exactly one `<h1>` per page, logical `h2`/`h3` order |
| **URLs and links** | Short readable file names, many internal links between pages, anchors for each service |
| **Mobile-friendliness** | Responsive layout from Part 2, viewport tag, large touch targets |
| **Page speed** | Hero reduced from 2.2 MB to about 55–155 KB (WebP + JPG fallback via `<picture>`, Mozilla, 2026), `defer` script, font `preconnect` + `display=swap`, gallery images as WebP |
| **Structured data / local SEO** | JSON-LD `LocalBusiness` (Sandton, Gauteng; areas served Johannesburg, Pretoria, Durban) following Google (2026c) and Schema.org (2026) |
| **Social sharing** | Open Graph and Twitter card tags with a 1200x630 image |
| **robots.txt + sitemap.xml** | Included; both reference the live URL |
| **Security** | Output built with `textContent`, honeypot field, `rel="noopener noreferrer"` on external links |

## 7. How to run and deploy

**Run locally:** open the folder in VS Code, right-click `index.html`, choose *Open with Live Server* (or double-click the file). Internet access is needed for the Google Fonts and the Leaflet map tiles.

**Deploy on GitHub Pages (free)** (GitHub, 2026):
1. Push the project to your GitHub repository (files in the repository root).
2. On GitHub open **Settings → Pages**.
3. Under *Build and deployment*, set **Source: Deploy from a branch**, branch **main**, folder **/ (root)**, then **Save**.
4. Wait 1–2 minutes. The site address appears at the top of that page.
5. Replace the placeholder URL (§6), commit and push again, then paste the live link at the top of this README and submit it.
